## 二、目标与不做

目标：
1. 家人不注册、不记密码、不用 AI 登录；「我的」里只有一个「家庭与设备」。
2. 每位家人有稳定身份（换手机不变），每台手机单独获准、单独停用。
3. 新手机由**管理者当面扫码批准**，钥匙直接加密交给这台手机；普通家人拿不到、也算不出恢复码。
4. 所有管理者的手机都丢了，还能凭恢复码重新接管；恢复码不再等于内容钥匙。
5. 空服务不能被抢先初始化。

不做（第十二节有理由）：公开注册、第三方登录、手机号／邮箱、多家庭／多孩子切换、多租户；撤销后换钥匙（密钥版本）推迟；逐人可见的私密信推迟；记录上加成员 id 推迟；给桉桉建账号。

## 三、防什么、不防什么

防：
- **丢手机**：管理者一键停用，那台手机立刻不能再连服务（同步、AI、管理都不行）。
- **服务器被人看了**（主机商、被入侵）：服务器上只有密文和加密后的钥匙包，没有 K，也没有恢复码。
- **服务器作恶／被冒充**：配对时新手机的公钥走二维码、不经服务器；新手机只接受「扫过它二维码的那台手机」封的钥匙包——服务器替换公钥或塞一把自己知道的钥匙都会被识破。
- **网上的陌生人**：不能抢先初始化；配对申请本身不带任何权限，转发二维码也没用。

不防（写进产品说明）：
- 已经在某台手机上的内容，停用后收不回；停用挡住的是以后的访问。
- 同一家人之间不设内容权限：拿到 K 的手机能读整本册子（「写给十八岁的信」暂不展示 ≠ 技术上读不到）。
- 管理者自己作恶；手机已被解锁并植入恶意软件。

## 四、概念与数据模型

| 概念 | 是什么 | 不拿它做什么 |
| --- | --- | --- |
| 家庭 `familyId` | 这一本共同的成长册；一台服务 = 一个家庭 | 不用服务地址或某人账号代替 |
| 家人 `memberId` | 爸爸、妈妈、外婆；换手机不变 | 不按昵称匹配，不因换机重建 |
| 设备 `deviceId` | 一次获准的 App 安装 | 不用硬件序列号、手机名当凭证 |
| 落款 `by` | 这段内容以谁的名义留下（已有） | 不当身份或权限依据；改名、停用家人都不改旧落款 |

角色只有两种：**管理者**（批准设备、增减家人、停用、额度、暂停 AI、重新生成恢复码）和**家人**（写、同步、用 AI）。可以有多位管理者（你和萌萌）。桉桉不建账号。

服务端表（SQLite，启动时迁移；旧列保留不删，只是不再使用）：
- `family`（单行）：`id`、`created_at`、`key_id`（当前 K 的指纹）、`recovery_envelope`（用恢复秘密封的 K，密文）、`recovery_verifier`（恢复证明的 sha256）、`recovery_version`。
- `members`：`role` 由 `owner|member` 迁成 `admin|member`（原主人 → 管理者）；`username`／`password_hash` 不再读写。家庭备份配额从「主人那一行」挪到 `settings`。
- `devices`：加 `public_key`（X25519，base64）、`last_used_at`、`approved_by`（批准它的设备）。令牌照旧是不透明随机串、只存哈希、服务端可随时撤销；**不改 JWT**。
- `pair_requests`：`id`、`created_at`、`expires_at`（10 分钟）、`public_key`、`device_name`、`claim_hash`、`status`（pending／approved／confirmed／cancelled／expired）、`member_id`、`device_id`、`approved_by`、`enc`、`ct`（钥匙包密文）、`token_once`（批准时生成、确认后清空）。
- `activation_codes`：`code_hash`、`expires_at`、`used_at`。只在空服务上有效。

## 五、三种秘密，三种职责

| 秘密 | 用途 | 谁持有 | 存在哪 |
| --- | --- | --- | --- |
| 设备令牌 + 设备私钥（X25519） | 向服务证明「我是一台获准设备」；接收给我的钥匙包 | 每台手机各自 | 系统钥匙串，仅本机、仅解锁后可读；不进任何备份 |
| 内容钥匙 K | 加解密远端的文字、照片、声音 | 所有获准手机 | 系统钥匙串（与现在相同） |
| 恢复秘密 R | 所有管理者手机都丢了时：解开 K 并重新取得管理权 | 管理者，**只抄在纸上** | 任何手机、服务器都不存；服务器只存用 R 封的 K 和 R 的证明的哈希 |

要点：
- **K 不变，远端格式不变。** 现在的对象 id、加密与清单全部照旧，已上传的内容不用重传。变的只是 K 怎么到达一台新手机（从「输 12 个词」变成「管理者扫码后加密交付」）。
- **R 与 K 各自独立随机生成**，R 不由 K 推导，K 也不由 R 推导。普通家人的手机从头到尾不接触 R。
- R 仍是 12 个英文词（128 位熵，沿用 BIP39 词表与现在的抄写／核对界面）。由 R 用 HKDF 分出两样东西：`wrap = HKDF(R, "anan-recovery-wrap-v1")` 用来封 K（XChaCha20-Poly1305，随机 nonce，AAD 绑定 `familyId‖keyId‖recoveryVersion`）；`proof = HKDF(R, "anan-recovery-auth-v1")` 交给服务端核对（服务端只存 `sha256(proof)`，看到 proof 也推不出 wrap）。
- 恢复码**只显示一次**（生成时），之后不能「查看」，只能由管理者「重新生成」——旧的一套立刻失效。
- 现在抄下的 12 个词（= 旧的 K）升级后作废；生产上远端清单为 0，没有人靠它。

## 六、流程

### 1. 初始化（空服务，一次）
部署端运行 `manage.ts activation`，打印一次性激活码（随机 128 位，24 小时内有效，用过即废，只存哈希）。主人的手机在「家庭与设备 → 开始一个家庭」输入激活码 → 手机生成 K（本机已有就沿用）、R、设备密钥 → 提交成员名（如「爸爸」）、设备公钥、`keyId`、恢复包与恢复证明哈希 → 服务端在一个事务里建家庭、建第一位管理者、登记设备、作废激活码 → 手机显示 12 个恢复词，核对其中 3 个后才算完成。`/setup`（用户名密码版）删除。

### 2. 现有主人手机升级（只发生一次）
1.0.8 的主人手机已持有令牌。1.1.0 首次打开时发现服务端还没有 `family` 行 → 显示「升级为家庭管理者」→ 同上生成 R、登记公钥、建家庭（凭现有主人令牌，不需要激活码）→ 显示新恢复码。这个升级接口只在「没有 family 行且调用者是原主人」时可用，之后永久 409。

### 3. 加一台手机（新增家人 / 给已有家人加设备）
1. 新手机「加入已有家庭」：本机生成 X25519 密钥对、32 字节一次性秘密 S、16 字节领取凭据 C → 向服务端登记申请（公钥、手机名、`sha256(C)`），拿到 `requestId`。这个接口不需要登录，按地址与全局限流，同时挂着的申请有上限。
2. 新手机显示二维码：`{v, requestId, 公钥, S}`。**S 和 C 都不经服务器**（S 只在二维码里，C 只在本机）。
3. 管理者在「家庭与设备 → 添加」扫码 → 从服务端取这条申请，**核对服务端给的公钥与二维码里的一致**（不一致就中止并提示）→ 明确选一个：
   - 「新增一位家人」：填称呼（如「妈妈」），选家人／管理者；
   - 「给已有家人加一台手机」：从名单里选人（妈妈换手机走这里，`memberId` 不变）。
4. 管理者手机把 `{K, familyId, keyId}` 用 **HPKE（RFC 9180）PSK 模式**封给新手机的公钥，PSK = S；`info` 绑定 `familyId‖requestId`，AAD 绑定 `{familyId, requestId, memberId, role, deviceName, 批准设备 id, keyId, 过期时间}` → 提交批准。服务端在一个事务里：（如需）建家人 → 登记设备（公钥取自申请）→ 生成新令牌 → 存钥匙包 → 状态改 approved。
5. 新手机凭 C 领取：`{令牌, memberId, deviceId, 钥匙包}` → 用私钥和 S 解开（服务器伪造的包解不开）→ 核对 AAD 里的家庭、成员、设备、`keyId = 指纹(K)` → 把令牌和 K 写进钥匙串 → 带新令牌调用「确认」→ 服务端清掉留存的令牌与钥匙包，状态改 confirmed。
6. 界面分开显示「已获准」和「第一次同步完成」。

边界情况：
- 批准后新手机断网：领取可以重复，直到确认；24 小时内没确认的设备自动撤销。
- 钥匙串写入失败：不确认，提示重试；超时后按上一条撤销。
- 二维码被转发：拿到的人没有私钥和 C，领不走也解不开；二维码本身不是凭证。
- 重放：同一 `requestId` 只能批准一次、确认一次；过期、取消、已确认的申请一律 409／410。
- 同一人重复申请：「给已有家人加手机」不会新建家人；「新增家人」遇到同名给出提示，要求改名或改选「已有家人」。
- 新手机本机已有记录：加入前明确提示「加入后，这台手机上已有的 N 段时光会和家人共享；草稿仍只在这台手机上」，确认后**先自动留一份本机备份**，再按现有三方合并并入，不整库替换。
- 第一版只做**当面扫码**（长辈的手机本来就是当面帮着装）。远程配对要另一条可信渠道核对安全码，推迟（第十三节第 3 条）。

### 4. 换手机
旧手机还在：用旧手机（或另一位管理者）按「给已有家人加一台手机」批准新手机，同步完成后再在旧手机上「退出这个家庭」或由管理者停用旧机。
旧手机丢了：先由管理者停用旧机，再批准新手机。已有的「本人被撤销设备的清单照给」（`14cbcbd`）保证旧机那份仍能并进新手机。

### 5. 停用设备 / 停用家人
停用设备：该令牌立刻失效（沿用 `revoked`）。停用家人：他名下所有设备一并失效；他写过的内容、落款都留着。**不能停用或降级最后一位启用的管理者，也不能撤销最后一位管理者的最后一台有效设备**（服务端事务里检查）。

### 6. 所有管理者手机都没了
新手机「用恢复码找回」→ 输入 12 个词 → 手机算出 proof 与 wrap → 服务端核对 `sha256(proof)` 后，列出家人名单让选「我是谁」（只能选管理者），登记这台为新的管理者设备并下发恢复包 → 手机用 wrap 解开 K、核对 `keyId` → 下载一份清单并解开，**真能读到内容才算恢复成功**。
成功后：作废所有未完成的配对申请；进入设备列表，提示逐台确认、停用丢失的手机；建议（不强制）立即重新生成恢复码。恢复接口严格限流；R 是 128 位随机数，猜不到。
还要写清楚：**恢复码不是备份**——它能解开远端的内容，不能变出远端没有的内容；定期导出 `.xmb` 仍然要做。

### 7. 最后一招（部署端）
所有管理者手机都丢了、恢复码也丢了，但还有家人的手机：部署者在服务器上运行 `manage.ts promote <家人称呼>`，把一位家人升为管理者（那台手机本来就有 K），他再重新生成恢复码。这替代现在的 `manage.ts password`。

### 8. 会话
令牌照旧不透明、服务端可撤销；新增 `last_used_at`（最多每小时写一次），**一年没用过的设备自动失效**，要重新批准。家人日常不会看到任何「登录」。

## 七、密码学实现约束

- 新增依赖只有 `@noble/curves`（X25519；与现在的 `@noble/ciphers`、`@noble/hashes` 同一作者、同一审计系列，纯 JS，Hermes 可用）。随机数照旧只取 `expo-crypto`。
- HPKE 用 RFC 9180 的标准套件 DHKEM(X25519, HKDF-SHA256) / HKDF-SHA256 / ChaCha20-Poly1305，PSK 模式；实现放在 `mobile/src/family/hpke.ts`，**必须通过 RFC 9180 附录 A.2 的官方测试向量（Base 与 PSK 两组）**，不自创配对算法。
- 家庭、成员、设备、批准者、申请、过期时间全部进 AAD／info；解包端逐项核对。
- 恢复包、钥匙包、恢复证明各自有版本号字段，将来换算法不用猜格式。
- 密码学与配对状态机单独成提交、单独评审，界面提交不改它们。

## 十二、外部评估里采纳与不采纳的

采纳：不做注册与第三方登录；成员与设备分离并保留现有基础；家庭身份从 AI 模块移出；恢复码与内容钥匙分离、普通家人推不出恢复秘密；初始化需要一次性激活凭据；配对绑定家庭／成员／设备公钥／批准者／一次性申请并处理替换、重放、过期、断网；用标准 HPKE 不自拼协议；服务端会话保持不透明可撤销并补过期；恢复码不是备份；备份不复制设备凭证；加入前确认、先留本机备份；AI 同意单独保留；「服务器看不到」限定到同步存储；新增家人与给已有家人加设备分开；首版所有新设备由管理者批准。

不采纳或推迟：
- **撤销后换钥匙（密钥版本）推迟。** 设备一停用，服务端就不再给它任何数据；服务器上本来也只有密文。只有「丢的手机」和「服务器被攻破」同时发生，换钥匙才多挡一层；代价是同步格式与所有手机的钥匙管理都要动。对象头已经带 `keyId`，以后要做不需要改格式。
- **记录上加 `createdByMemberId`／`createdOnDeviceId`／`updatedByMemberId` 推迟。** 落款已经是内容快照，满足「谁写的」；加成员 id 要改同步实体与合并，与本次授权改造无关。
- **恢复公钥（让管理者不用 R 就能重封）推迟。** 只有换钥匙时才需要；现在管理者手机本来就有 K，重新生成恢复码时直接用新 R 重封即可。
- **远程配对推迟。** 需要另一条可信渠道核对安全码，第一版当面扫码足够一家人用。
