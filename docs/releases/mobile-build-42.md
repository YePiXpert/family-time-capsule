# 原生构建 42：记录、相册与完整保存

产品版本仍为 `0.0.1`，Android versionCode / iOS buildNumber 均为 42。

## 使用变化

- 苔绿主题、系统无衬线字体与照片优先的记录布局；三个主页为「记录 / 相册 / 我的」，保留同一位置的「记一刻」。月份、第一次、搜索和选择直接可见。
- 全屏记录编辑统一新建、本机补记和服务器记录补充；照片、拍摄、录音直接可用，日期与读者一触调整。保存打开对应阅读页，再次编辑更新原记录。
- 本机相册可离线创建、命名、换封面、整理顺序与阅读。选材使用持久会话，跨月、分页及返回保留选择。
- 相册与成长册直接出现在同一书架；成长册提供直接换封面与并列内容、样式、导出入口。

## 配套服务器升级

先备份当前家庭数据与媒体，再按既有服务端升级流程升级到与本次 APK / IPA **相同 main 提交**并运行迁移。不要将新客户端的完整编辑能力与旧服务器混用。

- `0074_memory_edit_staging`：增量重建草稿表，保留旧草稿、上传及引用关系；旧草稿默认 `capture`，服务器记录新增素材使用独立 `memory_edit` 私密暂存。只有原子提交完成后素材才进入记录，暂存不能作为新记录发布或送入收件箱。
- `0075_collection_sync`：为本机相册增加客户端身份映射与操作回执。创建相册和初始条目同事务完成，追加只写新增条目，保留当前读者看不到的原条目。
- 服务器记录详情声明 `atomicEditVersion: 1`。客户端用同一个 `expectedRevision + mutationId` 保存正文、素材、封面与读者；响应丢失重试会核对原回执。版本冲突保留两份内容。
- 不支持完整保存的旧服务端会使本机编辑保留并提示升级，不显示部分保存成功。成长册排版与导出继续依赖服务器。
- 备份中的草稿模块升级到版本 2，恢复时保留暂存用途与封存状态。升级前备份仍按旧格式读取；旧版本不应恢复包含新模块的备份。需要回退时使用升级前备份，不能用旧应用写入已迁移数据库。

## 本机保存与首次同步

本机相册默认不上传。首次同步需明确当前家庭、相册名称与材料上传范围；联网本身不授权分享。相册不改变原记录的读者。未发布、待审核、失去权限或上传失败的材料保留待处理状态。

已同步相册可离线阅读已下载内容并暂存追加。远端名称、封面、排序与删除需要联网。编辑快照、选择会话和相册按服务器实例、账号、家庭隔离。

本机编辑原件受到引用保护；救援恢复保留编辑目标，等待核对后重新保存，不恢复为普通新记录或自动上传。

## 验证与安装包

交付前运行原生存储/同步/组件测试、服务器事务与迁移测试、Web 构建和既有回归检查。Native mobile packages 工作流从指定 main SHA 构建两种安装包，并执行 Release 模拟器启动、真实键盘、保存恢复、选材与本机相册阅读检查。截图和测试报告随对应 Actions 运行保存。

APK 可直接安装；IPA 是设备构建且未签名，供所有者自行签名。包内版本、来源 SHA 与工作流的 `FamilyTimeCapsule-build-source` 清单须一致。具体验证结果及下载链接以本次最终交付记录为准。
