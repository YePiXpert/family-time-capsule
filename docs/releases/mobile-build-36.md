产品版本 `0.0.1`，Android versionCode / iOS buildNumber 均为 36。原计划通过 `mobile-build.yml` 的明确 main SHA 成套构建 APK 与未签名设备 IPA；`v0.0.1` 的历史附件不变。

当前状态：`7adcbe2` 的常规 CI、Android 构建和 iOS Release 启动检查通过，[原生构建运行](https://github.com/YePiXpert/family-time-capsule/actions/runs/34672945642) 在 XCUITest 播放/布局步骤失败，未产出成套 IPA。维护者随后要求先实现竞品方案、暂停测试；新增源码进入 [构建 37](mobile-build-37.md)，后续需恢复原生验证和成套打包。构建 36 的 APK 不能充当新功能安装包。

## 行为变化

- 页面标题保持静态尺寸；同步提示使用独立浮层，不挤压导航，也不挡住返回按钮。后台同步不再触发下拉刷新动画。
- 记录页统一处理键盘与底部导航留白；已知封面的媒体区域保持尺寸，加载失败仍保留布局。
- 同步状态与资料订阅分开；未变化的记录保持引用，批量读取本机封面。长列表仍虚拟化，并保留阅读锚点。
- 点击视频后明确加载和播放，提供播放、暂停、重试；封面在真实首帧出现后收起。15 秒仍没有可用画面时提供恢复操作。
- 播放器在原件和兼容版之间切换时复用实例，保留播放位置和用户意图；关闭后释放，进入后台暂停。
- 在当前账号、家庭的草稿中有明确上传回执时，本机视频可以读取服务器已生成的兼容版；没有回执时不猜测关联，也不自行上传。
- 网络、登录权限、本机文件缺失、转码失败分别提示；无效媒体响应不会直接触发反复转码。

## 服务端核查

2026-09-12 在现有部署完成只读检查：app 与 worker 使用同一镜像和同一数据卷；FFmpeg 包含 H.264/AAC 编码器。已检查的视频为 MPEG-2/AC3，兼容 H.264/AAC MP4 与预览图均已生成。原件和兼容版通过内部入口及外部 HTTPS 入口的鉴权 Range 请求均返回正确的 `206`、类型、长度与范围。

本轮复用已有媒体接口和队列，无新增公共 API、数据库迁移或服务端部署要求。原件编码不受设备支持时，纯离线模式仍无法直接播放该原件；离线成长册目前下载原件，尚不自动另存兼容视频。

- 移动端单元与组件测试、类型检查和 lint；服务器媒体转码、鉴权分段请求及共享同步模块回归。
- `mobile-build.yml` 保留现有 iOS Release 启动、重启、深色与大字模式检查，并新增独立 XCUITest 阅读器、键盘和列表回归。测试运行器不进入安装包。
