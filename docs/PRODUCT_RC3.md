> 目标：不扩展 rc.3 产品范围，只收敛跨端数据正确性、权限体验、本机记录生命周期和真实设备发布前稳定性。

## 不可破坏边界

- 私有、自托管、单家庭优先；不引入 SaaS、公开社交、广告或遥测。
- `MemoryEvent` 仍是记忆主体，`Asset` 仍是不可覆盖的证据；SHA-256、来源与原始时间信息继续保留。
- `capturedAt`、`occurredAt` 与 `importedAt` 各司其职，不以导入时间冒充发生时间。
- AI 默认关闭且只提供待确认建议；无 Provider、Key 或 worker 时所有主路径仍可用。
- 不改变 portable archive 主版本、现有导出内容、恢复前置条件、家庭隔离与 Contribution 可见性策略。
- 原生端断开服务器、同步失败或单条素材失败时，本机记录与原件继续保留；`captureId` 重试保持幂等。

## 信息架构

Web 移动布局与原生端共享五个一级入口：

1. 首页：家庭近况、快速记录、待整理、最近记忆与重新遇见。
2. 时间轴：以图片和发生时间为主的长期浏览入口。
3. 记录：视觉突出的低阻力文字、照片、音频、视频与导入入口。
4. 收件箱：修改、合并、确认入档的工作区，并显示待整理数量。
5. 更多：搜索、家人、故事、口述史、时间胶囊、书籍与备份、设置、回收站。

桌面端用固定左侧导航同时呈现一级入口和次级入口；小屏 Web 与原生端用底部五项导航。搜索是全局动作，在桌面侧栏与移动顶栏均可到达，不额外占用一级标签。

## 交互原则

- 所有一级卡片与首页模块都必须有明确动作；空状态给出下一步，不写营销文案。
- 记录当下尽量在 10 秒内完成；复杂字段可选，默认进入收件箱稍后整理。
- 媒体优先于技术元数据；记忆默认是阅读体验，来源、哈希、任务和修订历史折叠在“档案信息”。
- 可见状态使用文字、形状与颜色共同表达；AI 内容统一标记“AI 生成 · 未确认”。
- 点击目标至少 44×44px；键盘焦点可见；异形屏安全区可用；减少动态偏好下关闭非必要动效。
- 375、768、1024、1440px 均无页面级横向滚动；长表格只在明确标注的局部容器内滚动。
- 只读、空数据、离线、同步中、单条失败与整体失败都有就近说明和安全重试动作。

## 服务边界

- 页面仪表盘、回顾、人物主页与移动 DTO 由 `lib/` 服务集中查询，页面不做逐项 N+1。
- 所有移动 API 从 Bearer session 的实时 User binding 推导 family、role 与 Person，不接受 `familyId`。
- 移动 API 复用既有 capability、Contribution visibility、软删除过滤和事件服务，不复制业务状态机。
- 新的成长节点是带类型/置顶展示信息的 `MemoryEvent`，不是第二套事件模型，也不承载高频照护数据。
